# Tab Group Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the service script, logrotate config and shell commands as three
tabs of an accessible `<tab-group>` custom element.

**Architecture:** `src/tab-group.ts` defines one custom element, `TabGroup`,
registered as `<tab-group>` when the module is imported. It pairs the nth
`<button>` of its `<tab-list>` with its nth `<tab-panel>`, applies the WAI-ARIA
tabs roles and states, and handles click and arrow-key selection. `index.html`
holds the markup; `src/main.ts` imports the module for its side effect.

**Tech Stack:** TypeScript, Vite, Vitest with happy-dom 21, no runtime
dependencies.

**Spec:** `docs/superpowers/specs/2026-11-17-tab-group-design.md`

## Global Constraints

- No runtime dependencies; add no packages.
- `npm test` must stay at 100% lines, branches, functions and statements over
  `src/**/*.ts`; no coverage exclusions (AGENTS.md).
- `npm run check` (ESLint, Stylelint, Prettier check, `tsc`, tests) passes
  before every commit. Run `npm run format` and `npm run lint:css:fix` before
  the linters. Never edit lint configuration.
- Prettier style: no semicolons, single quotes, width 100, two-space indent.
- Exact copy: heading `Generated files`; tabs `Service script`,
  `Logrotate config`, `Shell commands`; shell note
  `Run after saving the service script:`.
- No animation or transition on the tabs. Colours only from the tokens in
  `src/assets/base.css`.
- Tabs at least 24×24 CSS px; focus outline uses `--color-accent` (4.67:1 light,
  7.25:1 dark, so above the 3:1 minimum).
- Commits: semantic messages, no attribution trailers, never `--no-verify`,
  stage explicit paths only. Commit only once the user has authorised
  committing.

## Review Focus

- Home, End or an arrow key pressed inside a panel's textarea must move the
  caret, not switch tabs → test in Task 1 (keys outside the tabs).
- Browser shortcuts such as Alt+Left (back) or Ctrl+Home pressed on a tab must
  reach the browser → test in Task 1 (modified keys).
- Tab from the tab list must move focus into the panel, never be swallowed →
  test in Task 1 (`Tab` key left alone).
- A click on markup inside a tab button (an icon or `<span>`) must select that
  tab → test in Task 1 (click on the `<span>` in tab two).
- The selected tab must survive a field turning invalid (outputs hidden) and
  valid again → test in Task 2.

### Task 1: The `<tab-group>` element

**Files:**

- Create: `src/tab-group.ts`
- Test: `src/__tests__/tab-group.spec.ts`

**Interfaces:**

- Consumes: nothing.
- Produces: importing `src/tab-group.ts` registers `<tab-group>` (side-effect
  module; also `export class TabGroup extends HTMLElement`). Markup contract:
  `<tab-group>` > `<tab-list>` > `<button id>`… and `<tab-group>` >
  `<tab-panel id>`…, paired by order. On connect the first tab is selected and
  focus is not moved.

- [ ] **Step 1: Write the failing tests** in `src/__tests__/tab-group.spec.ts`,
      first line `// @vitest-environment happy-dom`, importing `'../tab-group'`
      once at the top. Fixture and helpers:

```ts
const fixture = `
  <tab-group>
    <tab-list>
      <button id="t1" type="button">One</button>
      <button id="t2" type="button"><span>Two</span></button>
      <button id="t3" type="button">Three</button>
    </tab-list>
    <tab-panel id="p1"><p>First</p><textarea></textarea></tab-panel>
    <tab-panel id="p2">Second</tab-panel>
    <tab-panel id="p3">Third</tab-panel>
  </tab-group>`
// mount(html = fixture): document.body.innerHTML = html
// tabs(), panels(): the buttons and tab-panels in document order
// selected(): index of the tab whose aria-selected is 'true'
// key(target, key, init = {}): dispatch a bubbling, cancelable
//   KeyboardEvent('keydown', { key, ...init }) on target and return it
```

Tests (assertions as stated):

- `wires roles and links each tab to its panel`: `tab-list` role `tablist`; tab
  _i_ role `tab`, `aria-controls` = `p{i}`; panel _i_ role `tabpanel`,
  `aria-labelledby` = `t{i}`, `tabindex` attribute `'0'`.
- `selects the first tab on connect without moving focus`: `aria-selected`
  `['true','false','false']`; `tabindex` `['0','-1','-1']`; panel `hidden`
  `[false,true,true]`; `document.activeElement` is `document.body`.
- `selects and focuses a clicked tab, including a click on its content`: click
  the `<span>` in `t2` → `selected()` 1, `activeElement` `t2`, panel `hidden`
  `[true,false,true]`; click `t3` → `selected()` 2.
- `it.each` `%s from tab %i selects tab %i`, rows `['ArrowRight',0,1]`,
  `['ArrowRight',2,0]`, `['ArrowLeft',0,2]`, `['ArrowLeft',1,0]`,
  `['Home',2,0]`, `['End',0,2]`: click tab _start_, press the key on it →
  `selected()` and `activeElement` are tab _expected_, and the event's
  `defaultPrevented` is `true`.
- `it.each` `leaves %s alone`, rows: `Tab` on `t1`; `ArrowLeft` with
  `altKey: true` on `t1`; `Home` with `ctrlKey: true` on `t1`; `End` with
  `metaKey: true` on `t1`; `ArrowRight` on `p1`'s `<textarea>` → `selected()`
  stays 0 and `defaultPrevented` is `false`.
- `ignores a click outside the tabs`: click `p1`'s `<p>`, then the `<tab-list>`
  itself → `selected()` stays 0.
- `it.each` `rejects markup with %s`: `expect(() => mount(html)).toThrow(msg)`:
  - no tab list, `<tab-group><tab-panel id="p"></tab-panel></tab-group>` →
    `<tab-group> needs a <tab-list> with at least one <button>`
  - an empty `<tab-list>` → the same message
  - the fixture without `p3` → `<tab-group> has 3 tabs but 2 panels`
  - the fixture without `id="t2"` →
    `<tab-group> needs an id on every tab and panel`
  - the fixture without `id="p2"` → the same message
- `registers once when the module is evaluated again`: `vi.resetModules()`, then
  `await import('../tab-group')` resolves, and `customElements.get('tab-group')`
  is defined. (happy-dom, like browsers, throws on a second `define` of a name;
  `main.spec.ts` re-imports the module for every test.)

- [ ] **Step 2: Run the tests to verify they fail**

Run: `npx vitest run src/__tests__/tab-group.spec.ts` Expected: FAIL,
`Failed to resolve import "../tab-group"`.

- [ ] **Step 3: Implement `TabGroup` in `src/tab-group.ts`**

- `constructor()`: add the `click` and `keydown` listeners on `this`, once per
  element, so moving the element does not stack listeners. Read no children
  here: an element can be constructed before they are parsed.
- `connectedCallback(): void`: find `:scope > tab-list > button` and
  `:scope > tab-panel`; validate in the order of the messages above (happy-dom
  rethrows a `connectedCallback` error from `innerHTML`; browsers report it to
  `window.onerror`); set `role` on list, tabs and panels, `aria-controls`,
  `aria-labelledby`, panel `tabIndex = 0`; then `select(0)`.
- `private select(index: number): void`: `aria-selected`, `tabIndex` (0 or -1)
  and panel `hidden` for every pair. It does not focus; the click and key
  handlers call `focus()` on the new tab.
- Click: `(event.target as Element).closest('button')`, its index in the stored
  tabs; ignore -1.
- Keydown: act only when the target is one of the stored tabs and none of
  `altKey`, `ctrlKey`, `metaKey` is set. ArrowLeft/ArrowRight wrap, Home is 0,
  End is the last; any other key returns without `preventDefault()`.
- Registration at the bottom, with a comment giving the re-import reason:
  `if (!customElements.get('tab-group')) customElements.define('tab-group', TabGroup)`.
- A file comment saying why the element exists and that it follows the WAI-ARIA
  APG tabs pattern with automatic activation; doc comments on why, not what.

- [ ] **Step 5: Style the tabs in `src/assets/main.css`**

  `border-bottom: 1px solid var(--color-border)`.

  `--color-text`, transparent background, no border except a 3px transparent

  border.
- `tab-list button:focus-visible, tab-panel:focus-visible`:
  `outline: 2px solid var(--color-accent)`, `outline-offset: 2px`.
